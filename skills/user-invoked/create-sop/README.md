# create-sop

将口述、聊天记录或既有的流程说明整理为可执行的 DAG 标准作业程序（SOP）。运行规则以 [SKILL.md](SKILL.md) 为准；本页说明如何发起和阅读产物。

## 适用场景

- 客服、运维、财务、合规或技术流程需要固化为可交接的 SOP。
- 原始描述有步骤、角色、条件判断、系统操作或异常处理，但尚未形成统一文档。
- 希望识别可并行工作与真实前置依赖，而不只是生成线性清单。

它不会替代需求澄清、架构决策或实际执行；未提供且会影响操作的事实会标为 `[confirm: …]`。

## 发起方式

```text
$create-sop

把下面的客户退款流程整理为中文 Markdown SOP，供客服专员执行。
输出应包含责任人、系统、留存证据、异常升级和 Mermaid DAG；
信息不完整时使用 [confirm: …]，不要自行补充规则。

<粘贴流程说明>
```

可额外指定文档位置、读者、术语、格式规范或范围边界。

## 产物怎么读

生成的 SOP 包含：

1. Purpose、Scope、角色和前置条件。
2. Run graph：以 Mermaid 和节点表表示依赖。
3. Nodes：每个节点只在这里保存详细操作、证据和决策规则。
4. 异常/升级终点、完成记录与 Open items。

图中的边 `A → B` 表示 B 被 A 阻塞；`frontier` 表示当前满足条件、可立即执行的节点。节点只在拥有者的章节中定义一次，图表仅用于导航。

## 使用示例

```text
$create-sop

将“微服务升级 common 包”的操作写成 SOP：先同步 origin/master，
使用 git worktree 创建升级分支，更新 go.mod 中的 common 版本，
执行测试，提交并推送。开发人员负责执行，金额或生产发布不在范围内。
```

输出会将“同步基线”“准备 worktree”“更新依赖”“验证”“提交和推送”划分为节点；只有真正依赖前一节点输出的操作才会形成阻塞边。

## 质量检查

在交付前，技能会检查：DAG 无环、节点无遗漏或重复归属、分支都有终点、异常有升级路径，并区分事实、假设和待确认项。
