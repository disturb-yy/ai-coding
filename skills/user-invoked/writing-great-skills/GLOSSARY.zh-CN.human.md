# Glossary — 写好 Skill 的术语表

> 维护规则：修改英文版 `SKILL.md` 或 `GLOSSARY.md` 时，必须同步修改本中文版本。
>
> 模型可读性规则：本文件是仅供人类阅读的中文镜像，不是 skill 入口。不要把它命名为 `SKILL.md`，不要添加 skill frontmatter，不要从英文 `SKILL.md` 链接到本文件，也不要在模型可调用的描述中引用它。

这是“什么让一个 skill 变好”的领域模型。Skill 的存在，是为了从随机系统里拧出确定性；根本美德是 **可预测性**，下面每个术语都是作用于它的杠杆。这是 [`writing-great-skills`](SKILL.zh-CN.human.md) 的披露式参考材料。

术语按轴线分组：**调用方式**（skill 如何被抵达）、**信息层级**（内容如何安排）、**牵引**（agent 运行时行为如何被塑形）、**修剪**（如何保持精简）。每个 **失败模式** 都放在能治疗它的杠杆旁边，并标记为 _失败模式_。

任何定义里的 **粗体术语** 都在本术语表中定义；按标题查找。

## 可预测性

Skill 让 agent 每次运行都以同一种 _方式_ 行动的程度，也就是同一个过程，而不是同一个输出（一个头脑风暴 skill 应该 _可预测地_ 发散；它的 token 会变化，但行为不会）。这是其他每个术语服务的根本美德；成本和可维护性是它的症状，不是它的竞争目标。

_避免使用_：一致性、可靠性、鲁棒性、输出确定性

## 调用方式

Skill 如何被抵达，以及这个选择要支付的两种负载。

### 模型调用型

保留 **description** 字段的 skill，因此 agent 可以看见它并自主触发它；人类仍然可以输入它的名字，所以模型调用总是 _包含_ 用户可达性。不存在“仅模型可用”的状态：description 只会增加 agent 发现能力，不会移除人类能力。它为这种可发现性支付永久 **上下文负载**，因为每轮都加载 description。它也可被其他 skill 抵达，因为使它能被 agent 发现的 description 同时使它可被调用。一个全是 **参考材料** 的模型调用型 skill，也可以成为共享参考材料的家：另一个 skill 可以调用它，因此多个 skill 都需要的参考材料可以放在一个地方。只有当 agent 必须自主触达这个 skill 时，才选择模型调用；如果它从不手动之外触发，就去掉模型调用能力，不支付上下文负载。

_避免使用_：能力、工具、capability

### 用户调用型

对 agent 隐形、只能由人类输入名字触达的 skill（user-_only_，而 **模型调用型** 是 user-_and-agent_）。它用 agent 可发现性换取零 **上下文负载**。因为它没有模型可用的触发描述，所以除了人类之外没有东西可以抵达它：没有其他 skill 可以触发它。

_避免使用_：流程、工作流、命令

### Description

Skill 的机器可读触发器，也是 **模型调用型** skill 被迫常驻加载的那个 **上下文指针**。它的模型可见性就是调用轴：让它对模型可见，skill 就是模型调用型（也可被其他 skill 抵达）；禁止模型调用，skill 就是 **用户调用型**，只能由人类抵达。它是模型调用型 skill 的 **上下文负载** 来源。

_避免使用_：frontmatter、摘要

### 上下文指针

一个留在 agent 上下文里的引用，命名某个上下文外材料，并编码抵达它的条件。**description** 是顶层上下文指针（上下文窗口 -> skill）；指向披露文件的指针是下一层的同类对象。它的措辞，而不是目标，决定 agent _何时_ 抵达，以及 _多可靠地_ 抵达。必须读取的目标如果躲在措辞薄弱的指针后面，就是一个方差 bug：先修正措辞，只有锐化失败时才把材料拉回内联。

_避免使用_：链接、引用、import

### 上下文负载

**模型调用型** skill 加到 agent 上下文窗口里的成本，也就是它常驻加载的 **description**，同时消耗 token 和注意力。**用户调用型** skill 通过没有模型可见 description 来逃开这个成本；它也是拆出更多模型调用型 skill 时的刹车。

_避免使用_：token 成本、上下文膨胀

### 认知负载

**用户调用型** skill 加给人类的成本：人类必须记住哪些 skill 存在，以及何时该使用哪个 skill（人类就是索引）。**模型调用** 通过 agent 可发现性移除这种成本；它也是拆出更多用户调用型 skill 时的刹车。它不是一个要最小化的成本：它是人类能动性的价格，也是一些 skill 应该保持用户调用型的理由。把它花在人类判断重要的地方；在不重要的地方移除它。

_避免使用_：人类索引、负担、开销

### 路由 Skill

一个 **用户调用型** skill，职责是指向你的其他用户调用型 skill：列出每个 skill 以及何时该使用它。这样人类只需要记住一个 skill，而不是许多个。它只能提示，不能触发：用户调用型 skill 没有模型可见 **description**，所以除了人类之外没有东西可以抵达它。当用户调用型 skill 增多时，它是 **认知负载** 的解法。

_避免使用_：dispatcher、菜单、注册表、索引、router procedure

### 粒度

你把 skill 划分得多细。更细的划分会消耗两种负载之一：更多 **模型调用型** skill 消耗 **上下文负载**（更多 description 挤进窗口并争夺注意力）；更多 **用户调用型** skill 消耗 **认知负载**（人类要记住并触达更多东西）。两种切法指导划分。按 **调用方式**，当你有一个不同 **引导词** 可以触发它，也就是你确实会在 prompt 中使用的触发词时，拆出一个模型调用型 skill。按 **序列**，当一串 **步骤** 中某一步的 **完成后步骤** 需要被隐藏时拆分，因为把它隔离到自己的上下文里会清空后续内容。也要小心反向操作：合并序列会让每一步都看见后面的完成后步骤，招来过早完成。

_避免使用_：chunking、模块化

## 信息层级

Skill 内容如何安排，以及每块内容位于梯子多深的位置。

### 信息层级

Skill 内容按 agent 多么立即需要它来排序的一架梯子，由两个切口产生：文件内还是指针后、步骤还是参考材料。层级如下：

- **步骤**：文件内，主层级
- **参考材料**：文件内，次层级
- **参考材料**：披露式，位于 **上下文指针** 后

没有 **步骤** 的 skill 只使用底下两层，通常会是合法的平铺同级集合（例如一次 review 的每条规则都在同一层），这是好安排，不是坏味道。层级与调用方式无关：一个 skill 可以是模型调用型或用户调用型，也可以全是步骤、全是参考材料，或两者都有。当 skill 有步骤时，本应披露的文件内参考材料会埋没步骤，并让 agent 是否关注步骤变成掷硬币；这不只是可读性杠杆，也是方差杠杆。保持梯子顶部清晰；能向下推的都向下推。

_避免使用_：结构、组织、布局

### 步骤

Agent 执行的有序动作。当 skill 有步骤时，它们是内容的主层级，也是值得放进 `SKILL.md` 的部分。不是每个 skill 都有步骤：一个 skill 可以全是步骤（`tdd`）、全是 **参考材料**（一次 review），或者两者都有，这与调用方式无关。每个步骤都以一个 **完成标准** 结束，无论清楚还是含糊。

_避免使用_：workflow、instructions、choreography

### 参考材料

Agent 按需查阅的材料：定义、事实、参数、例子、条件性指令。当 skill 有 **步骤** 时，它次于步骤；当 skill 没有步骤时，它就是全部内容；它也可以完全位于任何 skill 之外，见 **外部参考材料**。它通过 **上下文指针** 抵达，是 **渐进披露** 的首要候选。

_避免使用_：supporting material、docs、background

### 外部参考材料

位于 skill 系统之外的 **参考材料**：一个普通文件，没有 **description**，没有 **步骤**，不可调用。它是共享参考材料的家，前提是这些材料不需要自己触发；它也是两个 **用户调用型** skill 唯一能共享的家，因为二者都没有模型可见 description，所以不能互相触发。

_避免使用_：doc、resource、knowledge base

### 渐进披露

把 **参考材料** 沿梯子向下移动：从 `SKILL.md` 移到 **上下文指针** 后，让顶部保持清晰。它首先不是 token 优化，而是保护 **信息层级** 的方式。它由 **分支** 授权：只被某些分支需要的内容可以披露，每条路径都需要的内容内联；如果指针对必须读取的材料触发不可靠，先锐化措辞，只有失败时才拉回内联。

_避免使用_：lazy loading、chunking

### 共址

把 agent 同时需要的材料放在一个地方：一个概念的定义、规则和 caveat 放在同一标题下，而不是散落在文件里。这样读到一部分时也会带出相邻内容。它是 **信息层级** 的文件内伙伴：层级决定一块内容 _放多深_；共址决定它到了那里之后 _和什么放在一起_。一组 **参考材料** 的正确正文格式没有公式；测试是 skill 应该读起来像给 agent 写的文档，而被成组放置的材料比散落材料更像这样。它不同于 **重复**：重复是在两个地方复述同一含义；散落是把一个含义碎片化到多个位置。

_避免使用_：grouping、clustering、cohesion

### 蔓延

_失败模式。_ 一个 skill 单纯太长，也就是 `SKILL.md` 行数太多，与这些行是否陈旧或重复无关。即使一个 skill 全部内容都是活的、唯一的，也可能蔓延。它消耗可读性（agent 在行动前必须趟过更多内容，注意力在多余内容上变薄）、可维护性（每多一行，都是一行要保持 **相关** 的内容）和 token。解法是 **信息层级**：把 **参考材料** 推到 **上下文指针** 后，并按 **分支** 或序列拆分，让每条路径只携带自己需要的内容。它不同于 **沉积**（因陈旧累积而变长）和 **重复**（因复述含义而变长）：蔓延就是长度本身，无论原因是什么。

_避免使用_：膨胀、长度、大小、冗长

## 牵引

把 agent 运行时行为塑形成 **可预测性** 的杠杆。

### 分支

Skill 可以被调用的一种不同方式，也就是 skill 处理的一种情况，因此不同运行会走过 skill 的不同路径。一个有许多步骤的 skill 可能携带许多分支；一个线性 skill 没有分支。

_避免使用_：path、case、fork

### 概念空间

Skill 的紧凑边界图。它定义 skill 应该把 agent 拉向的目标区域、应该排除的偏离区域、决定取舍的优先维度、进入和退出条件、输出前检查，以及运行后应该保留或修剪什么的沉积规则。当 skill 边界模糊、多分支、或容易漂移时，它有用。若它只是复述 **description**、**引导词** 和 **完成标准** 已经让其可检查的内容，它就是 **空操作**。

当边界需要作为一个稳定对象被扫描或编辑时，用 Markdown prose 加 YAML block。让它与被它约束的行为 **共址**；只有当某些 **分支** 需要它、其他分支不需要时，才披露出去。

_避免使用_：范围、rubric、framework、checklist

### 引导词

一个已经存在于模型预训练中的紧凑概念，也叫 _Leitwort_，agent 在运行 skill 时会用它思考。它通过调用模型已经拥有的先验，用尽可能少的 token 编码一个行为原则（例如 _lesson_、_proximal zone of development_、_fog of war_、_tracer bullets_）。它作为 token 反复出现，而不是作为句子反复出现，跨越 skill 积累一个分布式定义，并锚定整片行为区域。你也可以造词，只要定义清楚；但自造词不会借到先验，你要用定义 token 支付一个预训练词免费提供的东西。先找现成词。

引导词以两种方式服务 **可预测性**。在正文中，它锚定 **执行**：每当这个概念出现时，agent 会抵达同一类行为；在平铺参考材料里，它会把注意力集中到要检查的一类东西上，每次运行都招募正确检查。在 **description** 中，它锚定 **调用**；而且不只在 skill 内：当同一个词存在于你的 prompt、文档和代码库时，agent 会把共享语言连接到 skill，更可靠地触发它。用你真正会在需要该 skill 时使用的引导词来写 description。

_避免使用_：keyword、term、motif

### 完成标准

告诉 agent 一个工作单元已经完成的条件，也就是它用来判断的目标。两个属性让它成为杠杆，而不只是质量。它的 **清晰度**（agent 能不能区分完成与未完成？）抵抗 **过早完成**：含糊边界（“理解已经达成”）会让 agent 宣称完成并滑向下一步；这个轴需要 _步骤_ 才能咬住，因为过早完成是步骤之间的失败。它的 **要求强度**（要求多少）设置 **实地工作**：“每个修改过的模型都已纳入” 会迫使工作充分，而 “产出一份修改清单” 不会；这个轴 _不_ 绑定步骤：它也可以约束一组平铺参考材料，这就是无步骤 skill 仍然能携带穷尽性门槛（“每条规则都已应用”）的方式。最强的标准既可检查又穷尽。

_避免使用_：done condition、exit condition、stopping rule

### 实地工作

Agent 在单个步骤内部幕后做的工作：读文件、探索代码库、修改、挖出所需材料，而不是把问题抛给用户。它位于步骤结构之下：永远不写成自己的步骤，而是潜伏在措辞里，由 agent 控制而不是由 skill 控制。它是 **完成后步骤** 跨步骤牵引的步骤内对应物。它可以由 **引导词**（_comprehensive_、_thorough_）抬高，也可以由要求工作穷尽的 **完成标准** 抬高，包括作用于平铺参考材料的要求轴；这就是一个平铺参考 skill 能覆盖所有层级的原因。当要求缺失，或者 **过早完成** 截断步骤时，实地工作会变薄。

_避免使用_：scope、effort、diligence、coverage

### 完成后步骤

当前步骤后面的 **步骤**。当它们可见时，会把 agent 向前拉进 **过早完成**；它看见的越多，拉力越强。防御方式是通过拆分步骤序列隐藏它们。

_避免使用_：horizon、fog of war、lookahead

### 过早完成

_失败模式。_ 在当前步骤真正完成之前结束它，因为 agent 的注意力滑向完成这件事，而不是工作本身。这是步骤之间的失败：它需要 **步骤** 才会发生。一个没有步骤的 skill 如果提前停止，不是过早完成，而是在未满足要求下的薄 **实地工作**。它是两股力量的拉扯：可见的 **完成后步骤**（向前的拉力）和 **完成标准** 的清晰度（阻力；锋利、可检查的边界能稳住，含糊边界会让步）。含糊是必要条件：锋利边界无论有多少后续步骤可见，都能抵抗拉力，所以从不草率的步骤不需要防御。两个杠杆可以稳住会草率的步骤，但按顺序使用：**先锐化边界**，因为它局部且便宜。只有当标准不可避免地含糊，并且你实际观察到草率时，才 **隐藏后续步骤**；而隐藏只有跨越真实上下文边界才有效（用户调用型交接或 subagent 派发；内联的模型调用不会把后续步骤清出上下文）。它是薄实地工作的一种原因，但不同于薄实地工作：即使一个步骤运行到完整完成，实地工作仍可能很薄。

_避免使用_：premature closure、the rush、rushing、shortcutting

## 修剪

保持 skill 精简；每个疗法都配对它治疗的失败。

### 单一事实源

每个含义只存在于一个权威位置的理想状态，因此改变 skill 行为只需要改一个地方。**重复** 是对它的违反。

_避免使用_：home、canonical location

### 重复

_失败模式。_ 同一个含义有不止一个 **单一事实源**。它消耗维护成本（改一个地方，就必须改其他地方）、消耗 token，并膨胀显著性：重复一个含义，会把它在梯子上的权重抬到超过真实等级。它是 **引导词** 的意外反面；引导词是有意通过重复一个 token 提高注意力，而不是重复含义。

_避免使用_：repetition、redundancy

### 相关性

一行是否仍然支撑 skill 要做的事，这是决定保留什么的镜头。一行会失去相关性，可能因为它从未支撑任务（纯 exposition，或一个应该披露的 **分支**），也可能因为它变陈旧：随着行为或世界变化而漂移。较短的 skill 更容易保持相关，因为每一行检查起来更便宜。它不同于 **空操作**：相关性问的是一行是否支撑任务，不是它是否改变行为。

_避免使用_：load-bearing、staleness、freshness

### 沉积

_失败模式。_ 陈旧内容一层层沉到 skill 里，从不清理，因为添加让人感觉安全，删除让人感觉危险；于是陈旧和无关的行不断累积，你必须向下钻取才能找到仍然活着的东西。任何没有修剪纪律的 skill 默认都会走向这里；它是 **相关性** 的缓慢侵蚀，不同于 **重复** 的含义复述。

_避免使用_：accretion、bloat、cruft、rot

### 空操作

_失败模式。_ 一条指令没有改变任何东西，因为模型本来就会默认这么做；你付出了负载，却只是告诉 agent 它无论如何都会做的事。测试是：这一行相对默认行为有没有改变行为？一行可以完全 **相关**，同时仍然是空操作。同样的先验让 **引导词** 免费，也让空操作一文不值。

引导词是一种 _技术_；空操作是对一行的 _判决_，二者会交叉。一个太弱而不能击穿默认行为的引导词就是空操作（当 agent 已经有点 thorough-ish 时还说 _be thorough_），修复方式是换成能通过判决的更强词（_relentless_），而不是换技术。所以空操作测试，也就是“它相对默认行为有没有改变行为？”，同样可以用来评估一个引导词是否值得反复出现。这是相对模型的，不是相对读者的：两个人如果不同意某行是否是空操作，他们不同意的是默认行为，应该通过运行 skill 解决，而不是争论解决。

_避免使用_：redundant instruction、restating the obvious、belaboring
