# writing-great-skills 中文版

> 维护规则：修改英文版 `SKILL.md` 或 `GLOSSARY.md` 时，必须同步修改本中文版本。
>
> 模型可读性规则：本文件是仅供人类阅读的中文镜像，不是 skill 入口。不要把它命名为 `SKILL.md`，不要添加 skill frontmatter，不要从英文 `SKILL.md` 链接到本文件，也不要在模型可调用的描述中引用它。

Skill 的存在，是为了从随机系统里拧出确定性。**可预测性**，也就是 agent 每次运行都采取相同的 _过程_，而不是产出相同的结果，是根本美德；下面所有杠杆都服务于它。

**粗体术语** 在 [`GLOSSARY.zh-CN.human.md`](GLOSSARY.zh-CN.human.md) 中定义；需要完整含义时去那里查。

## 调用方式

有两种选择，各自支付不同成本：

- **模型调用型** skill 保留 **description**，因此 agent 可以自主触发它，其他 skill 也可以抵达它（你仍然可以手动输入它的名字）。它会贡献 **上下文负载**，因为 description 每轮都待在上下文窗口里。机制：省略 `disable-model-invocation`，并写一个面向模型的 description，带上丰富的触发措辞（例如 “Use when the user wants..., mentions...”）。
- **用户调用型** skill 把 description 从 agent 可触达范围里移除：只有你输入它的名字时才能调用它，其他 skill 也不能调用它。它没有上下文负载，但会消耗 **认知负载**：_你_ 就是那个必须记住它存在的索引。机制：设置 `disable-model-invocation: true`；此时 `description` 变成人类可读的一行摘要，去掉触发列表。

只有当 agent 必须自己触达这个 skill，或者另一个 skill 必须触达它时，才选择模型调用。如果它只会被手动触发，就做成用户调用型，不支付上下文负载。

当用户调用型 skill 多到你记不住时，堆起来的认知负载可以用一个 **路由 skill** 治疗：一个用户调用型 skill，列出其他 skill 以及何时该使用它们。

## 写 description

模型调用型 **description** 做两件事：说明这个 skill 是什么，并列出应该触发它的 **分支**。每个词都会增加 **上下文负载**，所以 description 比正文更需要狠剪：

- **把 skill 的引导词前置**，因为 description 是它发挥调用作用的地方。
- **每个分支只留一个触发条件。** 如果同义词只是给同一个分支换名字，那就是 **重复**。例如 “build features using TDD” 和 “asks for test-first development” 是同一个分支写了两次。合并它们；只保留真正不同的分支。
- **删掉正文里已经有的身份说明。** description 只保留触发条件，加上任何 “when another skill needs...” 的可达性子句。

## 信息层级

Skill 由两类内容构成：**步骤** 和 **参考材料**。它们可以自由混合：一个 skill 可以全是步骤，全是参考材料，或者两者都有。核心判断是该用哪一类，以及每一类应该放在 **信息层级** 的哪一层。信息层级是一架梯子，按 agent 多么立即需要这些材料来排序：

1. **skill 内步骤**：`SKILL.md` 中的有序动作，是主层级：agent 做什么，按什么顺序做。每个步骤都以一个 **完成标准** 结束，也就是告诉 agent 工作已经完成的条件。让它 _可检查_（agent 能不能判断完成和未完成？），并且在重要处让它 _穷尽_（“每个修改过的模型都已纳入”，而不是“产出一份修改清单”）。含糊标准会招来 **过早完成**。
2. **skill 内参考材料**：`SKILL.md` 中按需查阅的定义、规则或事实。它通常可以是合法的平铺同级集合（例如一次 review 的每条规则都在同一层）——这是好安排，不是坏味道。_本 skill 全是参考材料。_
3. **外部参考材料**：从 `SKILL.md` 推到单独文件里的参考材料，通过 **上下文指针** 抵达，只有指针触发时才加载。（范围包括 _披露式_ 参考材料，也就是像 `GLOSSARY.md` 这样的同目录文件，仍属于 skill；也包括完全的 **外部参考材料**，它位于 skill 系统之外，任何 skill 都可以指向它。）

高要求的完成标准会驱动充分的 **实地工作**，也就是 agent 在工作内部做的挖掘。无论 skill 是否有步骤都是如此，因为 “每条规则都已应用” 可以约束平铺参考材料，正如 “每个步骤都已完成” 可以约束一个序列。

向下推得太少，顶层会膨胀；向下推得太多，又会藏起 agent 实际需要的材料。整个判断都在这个张力里。

**渐进披露** 是沿梯子向下移动：把内容从 `SKILL.md` 移到链接文件里，让顶层保持清晰。机制：skill 文件夹里的一个已链接 `.md` 文件，名字说明它承载什么（本 skill 把完整定义披露到 `GLOSSARY.md`）。有些 skill 会以多种方式使用，每种不同用法就是一个 **分支**，也就是不同运行会走过 skill 的不同路径。分支是最干净的披露测试：每个分支都需要的内容内联，只被部分分支触达的内容放到指针后面。**上下文指针** 的 _措辞_，而不是它的目标，决定 agent 何时以及多可靠地抵达材料。

梯子决定一块内容 _放多深_，**共址** 决定它到了那里之后 _和什么放在一起_：把一个概念的定义、规则和 caveat 放在同一个标题下，而不是散落各处，这样读到一部分时也会带出相邻内容。

## 概念空间

**概念空间** 是一个给 skill 用的紧凑边界图：它说明哪些工作属于这个 skill 的目标区域，哪些工作属于偏离区域，哪些维度优先决定取舍，以及 agent 如何进入、退出、检查并沉淀结果。

当你创建或实质修改一个边界含糊、多分支、或容易漂移的 skill 时，加入概念空间。若现有 **引导词**、**description** 和 **完成标准** 已经让边界可检查，就不要加；那会变成 **空操作**。

当结构比 prose 更有用时，用 Markdown 加 YAML block 表达：

```yaml
conceptual_space:
  target_region: "这个 skill 负责塑形的工作。"
  deviation_region:
    - "这个 skill 必须拒绝、延后或路由到别处的相邻工作。"
  priority_dimensions:
    - "第一个要优化或保护的维度。"
    - "出现取舍时的下一个维度。"
  entry_conditions:
    - "说明 agent 应该使用这个 skill 的可观察线索。"
  exit_conditions:
    - "说明 skill 工作已完成的可检查条件。"
  pre_output_check:
    - "回答或编辑前的最终检查。"
  sedimentation:
    - "运行后需要更新、保留、披露或修剪的内容。"
```

把 `target_region` 和 `deviation_region` 当作 skill 的边界，把 `priority_dimensions` 当作取舍顺序，把 `entry_conditions` 当作调用压力，把 `exit_conditions` 当作完成标准，把 `pre_output_check` 当作最后一道方差护栏，把 `sedimentation` 当作防止成功修改变成陈旧层的规则。

## 何时拆分

**粒度** 是你把 skill 切得多细。每次切分都会消耗两种负载之一，所以只有切分收益足够时才拆。两种切法：

- **按调用拆分**：当你有一个应该独立触发的不同 **引导词**，或者另一个 skill 必须触达它时，拆出一个 **模型调用型** skill。你会为新的常驻 **description** 支付 **上下文负载**，所以独立可达性必须值得这个成本。
- **按序列拆分**：当后续 **步骤**，也就是某一步的 **完成后步骤**，会诱使 agent 草率跳过当前步骤（**过早完成**）时，拆分这一串步骤。把后续步骤藏出视野，会鼓励 agent 在当前任务上做更多 **实地工作**。

## 修剪

让每个含义都有一个 **单一事实源**：一个权威位置，这样改变行为只需要改一个地方。

逐行检查 **相关性**：它是否仍然支撑这个 skill 要做的事？

然后逐句猎杀 **空操作**，不要只逐行看。把每个句子单独做空操作测试；一旦失败，就删掉整个句子，而不是修剪几个词。要果断，大多数失败的 prose 应该删除，不是重写。

## 引导词

**引导词** 是已经存在于模型预训练中的紧凑概念，agent 在运行 skill 时会用它思考（例如 _lesson_、_fog of war_、_tracer bullets_）。它在文本中反复出现（但不一定必须反复出现；强引导词可能只需要一次），会积累一个分布式定义，并用最少 token 锚定整片行为区域，因为它借用了模型已经拥有的先验。

它以两种方式服务可预测性。在正文中，它锚定 _执行_：每次这个词出现时，agent 都会抵达同一种行为。在 description 中，它锚定 _调用_：当同一个词存在于你的 prompt、文档和代码中时，agent 会把这套共享语言连接到 skill，从而更可靠地触发它。

寻找机会把 skill 重构为使用引导词。一个三元组在三个地方展开（**重复**），一个 description 花一整句话指向一个概念，这些段落都在请求被 **折叠** 成一个 token。例子：

- “fast, deterministic, low-overhead” -> _tight_：同一个阶段反复陈述的一种品质，折叠进一个预训练词（a _tight_ loop）。
- “a loop you believe in” -> _red_：把模糊关口转换成二元可观察状态（这个 loop 要么在 bug 上变 _red_，要么没有）。

你会赢两次：token 更少，agent 思考时可挂靠的钩子也更锋利。假设每个 skill 都带着可以被引导词退休的复述，然后去找它们。

## 失败模式

用这些诊断用户可能在 skill 上遇到的问题。

- **过早完成**：在步骤真正完成前就结束，注意力滑向 _完成这件事_ 本身。防御顺序：先锐化完成标准（便宜、局部）；只有当标准不可避免地含糊，而且你实际观察到这种草率时，才通过拆分隐藏完成后步骤（序列切分）。
- **重复**：同一个含义存在于多个位置。它消耗维护成本和 token，并且把一个含义在梯子上的显著性膨胀到超过真实等级。
- **沉积**：陈旧层累积下来，因为添加让人感觉安全，删除让人感觉危险。任何没有修剪纪律的 skill，默认都会走向这里。
- **蔓延**：skill 单纯太长，即使每一行都是活的、独特的。它伤害可读性和可维护性，也浪费 token。解法是梯子：把 **参考材料** 披露到指针后面，并按 **分支** 或序列拆分，让每条路径只携带自己需要的内容。
- **空操作**：一行内容只是模型本来就会默认遵守的东西，所以你付出了负载却什么都没说。测试是：它相对默认行为有没有改变行为？弱引导词（例如当 agent 已经有点 thorough-ish 时还说 _be thorough_）是空操作；修复方式是换成更强的词（_relentless_），而不是换技术。
