# Exploring Project

> 本文件是 `SKILL.md` 的中文本地化副本，仅供人工阅读和发布展示使用。
> 严禁模型读取本文件作为操作指令或任务上下文。
> 修改英文版本 `SKILL.md` 时，必须在同一次变更中同步更新本中文版本。

## 本地化维护

- 如果修改英文 skill，必须在同一次变更中更新 `SKILL.zh-CN.md`。
- 不要把 `SKILL.zh-CN.md` 当作模型操作指令或任务上下文读取。它只是面向人的本地化副本。

## 角色契约

以本地 [`codebase_explorer`](role/codebase-explorer.md) 角色副本执行。探索前读取其链接的[角色交接标准](../../role/handoff-standard.md)。角色定义 context 阶段、只读边界、停止条件和交接字段；本 skill 定义探索方法。完成时交付 `target`、`relevant_files`、`flow`、`leads_checked`、`risks` 和 `next_change_location`，不得编辑文件。

## 目标

运行一个缩小范围的循环：界定请求，映射相关区域，导航到候选代码，在源码或测试中验证相关路径，然后在答案或下一处修改位置已经清楚时停止。除非定向发现失败，否则不要通读整个仓库。

## 工作流程

1. 界定目标。复述用户期望的结果，并命名目标行为、功能、路由、模块、流程或函数。只有当歧义会改变查找位置或修改内容时，才提出 1-3 个具体问题；每个问题都附上你的推荐答案。目标和假设明确后，本步骤完成。
2. 映射区域。可用时使用生成的项目指南和 Graphify 识别相关系统区域、领域概念、跨区域连接和可能边界。当你能命名可能区域，或说明 Graphify/指南不可用或无帮助时，本步骤完成。
3. 导航代码。可用时使用 CodeMap MCP 结果或 `.codemap/` 产物识别候选文件、函数、路由、flow、测试和剩余不确定点。在打开大量源码前完成本步骤。
4. 验证路径。使用目标 `rg`、源码文件和测试确认线索：路由/命令/UI -> 服务/用例 -> 模型/存储/集成 -> 测试。只有在相关行为已验证，或定向搜索证明预期路径不存在时，本步骤完成。
5. 输出可执行上下文。探索任务要报告已验证流程和证据。代码修改任务要指出下一处编辑位置、附近测试、职责边界和风险。当用户无需再次发现即可行动时，本步骤完成。

## 导航线索

在宽泛发现之前，使用最小可用指南。指南可以存在于仓库根目录，也可以存在于 package、module、app、service 或其他有明确边界的子树内部：

- 根目录 `.agent/PROJECT_INDEX.md`、`README`、文档、架构说明和贡献指南用于整体项目上下文。
- 根目录或目录级 `.agent/FEATURES.md` 用于业务能力和用户工作流。
- 根目录或目录级 `.agent/NAVIGATION.md` 用于该目录的职责、起始文件、相关模块、路由和测试。
- 根目录或目录级 `.agent/CHANGE_GUIDE.md` 用于变更触点、典型流程、测试和风险。

将根目录指南视为项目地图。将目录级指南视为该目录及其子树的介绍。已知候选目录后，优先读取最近的相关 `.agent/` 指南；只有当本地指南缺失或范围太窄时，才向父目录指南或根目录指南回退。不要假设每个目录都必须有指南。

只阅读与请求的功能、模块、路由、流程、目录或变更类型相关的小节。将生成指南视为导航线索，而不是事实结论；关键判断必须按下面的工具角色通过 Graphify、CodeMap、源码文件或测试验证。

## 工具角色

为问题层级选择最紧的可用工具：

| 层级 | 优先使用 | 适合 | 必须用以下内容验证 |
| --- | --- | --- | --- |
| 架构、领域概念、跨模块或代码/文档关系 | Graphify query/path/explain 或 `graphify-out/GRAPH_REPORT.md` | 核心抽象、社区、意外连接、宽泛系统区域 | 声称实现行为前，用 CodeMap、源码、测试或文档验证 |
| 代码结构、路由、模块、flow、调用链、影响面 | CodeMap MCP 或 `.codemap/` 产物 | 候选文件、handler、service、测试、变更点 | 源码和测试 |
| 精确符号、错误文本、配置、路径存在性、最终证明 | 目标 `rg`、`rg --files` 和源码读取 | 具体行和行为 | 最小相关实现/测试集合 |

当 Graphify 输出存在，且问题是宽泛架构、跨区域或概念相关时，先用它再用 CodeMap 或源码读取。当问题是路由、模块、flow、函数或变更点时，先用 CodeMap 再进行宽泛源码读取。当问题直接给出精确符号、错误、路径或配置键时，直接使用目标 `rg` 和源码读取。

当当前项目可用 `codemap` MCP server 时，在打开源文件之前先使用它：

| 目标 | CodeMap 工具 | 通过阅读以下内容验证 |
| --- | --- | --- |
| 宽泛需求或修改请求 | `find_change_points`，使用较小的 `top_k`，通常为 5 | 候选文件、函数、路由和测试 |
| 功能或用户工作流 | `get_feature_map`、`get_navigation_hints` | 入口文件、相关模块和测试 |
| HTTP/API 路由 | `search_route` | 处理器、服务/用例和路由测试 |
| 模块或包 | `search_module`、`related_modules` | 模块实现、导入和依赖方 |
| 流程或调用链 | `search_flow`、`call_graph` | 调用方/被调用方实现和集成测试 |
| 函数影响面 | `impact_analysis` | 调用方、行为契约和受影响测试 |

尽可能把 `.agent` 指南字段转换成聚焦的 CodeMap 调用：模块 -> `search_module` 或 `related_modules`；路由 -> `search_route`；流程 -> `search_flow` 或 `call_graph`；宽泛修改 -> `find_change_points`。

如果 CodeMap 不可用、过期、不支持当前项目或结果太模糊，则回退到轻量发现：`rg`、`rg --files`、清单文件、路由注册、导入、测试和主要入口点。如果 Graphify 不可用、过期或结果太模糊，不要用全仓源码扫描替代它；针对当前范围使用指南、CodeMap 和目标源码读取。

## 证据规则

- 优先使用 `rg` 和 `rg --files` 做精确发现和验证。
- 当 Graphify 可用且与宽泛架构或跨区域发现相关时，优先用它，而不是直接阅读原始源码。
- 当 CodeMap 可用且与路由、模块、flow、函数和影响面发现相关时，优先用它，而不是直接阅读原始源码。
- 使用依赖边、导入、路由注册、测试名称和配置文件来缩小搜索范围。
- 将代码命名、生成文档、Graphify 和 CodeMap 视为线索，而不是结论。
- 在解释行为或编辑代码前，必须阅读实现或测试来验证关键判断。
- 明确表达不确定性：用 `unknown` 或 `not found`，不要猜测。
- 一旦答案或下一步行动足够清楚，就停止探索。

## 检查点

- 在阅读指南/Graphify/CodeMap 后，先列出候选文件、函数、路由、测试和不确定点，再打开大量文件。
- 在解释行为或编辑代码前，通过源码或测试验证相关线索。
- 结束前，报告已验证流程和下一处编辑位置。如果验证失败，说明未找到什么，以及使用了哪种图谱、CodeMap 或定向搜索。

## 输出形式

只使用对当前任务有帮助的小节：

```text
项目形态：
- ...

相关文件：
- path: 为什么重要

已检查线索：
- 指南/Graphify/CodeMap/搜索结果 -> 已验证/未验证

流程：
- 入口 -> 实现 -> 持久化/集成 -> 测试

风险：
- ...

下一步修改位置：
- ...
```

对于代码修改，应使用这些发现来保持改动范围最小，并避免无关重构。

## 示例

### 明确的修改请求

输入：

```text
修复订单取消后没有返还库存的问题。
```

预期行为：

```text
复述返还库存的目标。使用指南和 `find_change_points`，然后对任何被点名的路由、流程、模块或函数使用聚焦 CodeMap 工具。只阅读验证取消 -> 库存流程所必需的候选实现和测试，再开始编辑。
```

### 模糊请求

输入：

```text
优化登录流程。
```

预期行为：

```text
提出 1-3 个问题，因为“优化”可能改变探索路径。附上推荐答案，例如：“推荐：聚焦密码登录失败后的用户可见错误。”用户接受或纠正目标后，运行导航和验证循环。
```

### CodeMap 不可用或结果较弱

输入：

```text
找出这个项目在哪里生成发票。
```

预期行为：

```text
先尝试 CodeMap。如果不可用或结果较弱，则阅读最小相关指南，并使用 `rg`/`rg --files` 搜索发票相关词、路由、测试和入口点。最终答案必须通过阅读相关实现或测试来验证。
```

### 宽泛架构或跨区域问题

输入：

```text
Explain how market sync connects API handlers, providers, repositories, and docs.
```

预期行为：

```text
如果存在 `graphify-out/`，先用 Graphify 识别核心概念和跨区域连接。使用 CodeMap 的 routes/modules/flows 定位候选 handler、service、provider、repository 和测试。回答前使用目标 `rg` 和源码读取验证实际路径。
```
