# 记忆生成

## 角色契约

以本地 [`memory_generator`](role/memory-generator.md) 角色副本执行本 skill。开始前读取当前任务的 `AGENTS.md` 本地记忆规则和[角色交接标准](../../role/handoff-standard.md)。角色定义写入权限、停止条件与交接字段；本 skill 定义分层、去重、生命周期和安全持久化流程。所有持久化写入必须 direct 执行，并在完成时报告 `memory_records`、`deduplication_decision`、`retention_decision`、`validation` 与 `handoff`。

仅持久化会实质改善后续工作的信息。将记忆视为紧凑、已验证的稳定事实索引；不得把它当作聊天存档或当前来源的替代品。

## 记忆分层架构

按 `type → scope → record` 组织逻辑空间：`type` 仅可为 `feedback`、`user`、`project` 或 `reference`；`scope` 限定为全局、项目或外部系统；一条 `record` 只承载一个稳定事实或指引。

每条记录必须分为三层：

- **L0 摘要层**：`summary` 用一句话说明记忆和相关条件，支持快速筛选，不含敏感细节。
- **L1 核心层**：`content` 与类型、范围、标签、约束和生命周期字段共同构成可执行的已验证记录。
- **L2 证据层**：`evidence_refs` 只保存源文件、URL、工件或验证位置的指针；不得复制原始聊天、完整日志或源文档。

按 L0 → L1 → L2 递进读取：L0 不足以决定相关性时读取 L1；仅在核验、冲突处理或需要详细背景时追溯 L2。更新 L1 时同步检查 L0 是否仍准确；不得把 L2 当作 L1 的替代品。

## 工作流

1. 先读取活跃的 `feedback` 与 `user` 记录。仅在需要项目背景时读取当前项目记录；仅在外部来源会影响结论时读取 `reference` 记录。
2. 将候选内容归为 `feedback`、`user`、`project` 或 `reference` 之一。拒绝原始聊天、长日志、秘密、个人数据、短暂状态、推测性结论和当前工件已包含的信息。
3. 验证候选内容的来源、范围、稳定性与未来价值；其中任一不清晰时不得持久化。
4. 在相同类型与范围的活跃记录中搜索等价项。存在等价项时重写该记录，而不是创建重复项。
5. 按记忆分层架构生成 L0 `summary`、L1 核心记录和 L2 `evidence_refs`。每行不得超过 150 个字符。
6. 设置或保留 `status`、`review_after` 与 `valid_until` 等生命周期字段。依赖记录前先标记过期内容；不得静默刷新其主张。
7. 验证记录真实、在范围内、非敏感、已去重且有用。报告存储决定和下一步。

## 存储决策

持久化明确的用户偏好、已验证的项目约定或决策、稳定的外部指针、可复用流程或持久阻塞。

活跃等价记录存在且新事实取代或修正它时更新。复查日期或有效期已过时标记为过期。审查后没有稳定、已验证价值时跳过存储。

## 记录形态

使用仓库既有的记录 schema。至少明确类型、范围、L0 稳定摘要、L1 已验证内容与生命周期、L2 证据指针和标签。将原始材料保留在记录外。

不得仅因读取记录就增加 `recallCount`；只有该记录实质改变当前工作时才增加。

## 交接

其他角色需要结果时，仅交接记录位置、存储决定、证据引用、生命周期状态和未解决风险。持久写入使用 direct 执行；不得使用程序化批处理执行有副作用的记忆写入。

## 禁止事项

- 不得因一次偶然有效的观察创建记忆。
- 不得向用户询问仓库或权威来源能够验证的事实。
- 不得将源文档、日志或聊天记录复制进记忆。
- 不得写入秘密或敏感个人数据。
- 不得修改确认范围之外的记忆记录。
